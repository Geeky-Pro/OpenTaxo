## 1. النموذج رباعي المستويات

يفرض النموذج فصلاً هندسياً ودلالياً قاطعاً بين **الهيكل الملاحي العام للتصفح** وبين **مخططات مواصفات المنتجات**:

| المستوى | نوع العقدة | الوصف الدلالي | هل يمكن أن يحتوي أبناء؟ | هل يمتلك خصائص مرتبطة؟ | مثال عملي |
| :--- | :--- | :--- | :---: | :---: | :--- |
| **0** | `department` | القطاع التجاري الرئيسي الأوسع في المنصة | نعم (`category` فقط) | ❌ لا | `الإلكترونيات والأجهزة الكهربائية` |
| **1** | `category` | مجال أو خط منتجات رئيسي | نعم (`subcategory` أو `product_type`) | ❌ لا | `أجهزة الحاسوب المحمولة` |
| **2** | `subcategory` | تقسيم تخصصي اختياري | نعم (`product_type` فقط) | ❌ لا | `حواسيب الألعاب الاحترافية` |
| **3** | `product_type` | التصنيف النهائي للسلعة القابلة للبيع | ❌ لا (ورقة نهائية فقط) | ✅ **نعم (حدود المخطط الوحيدة)** | `حاسوب محمول فائق الأداء` |

## 2. القواعد الهندسية الثابتة (Invariants)

### القاعدة 2.1: حصر ربط الخصائص في العقد الورقية فقط
> **قاعدة غير قابلة للتفاوض**: *نوع المنتج (`product_type`) هو العقدة الوحيدة التي تمتلك مخطط خصائص؛ العقد العليا (`department`, `category`, `subcategory`) مخصصة للملاحة والتصفح وتجميع المنتجات فقط.*

- **التعليل الهندسي**: في منصات التجارة الإلكترونية، يؤدي السماح للعقد العليا المجردة بتعريف خصائص إلى مشاكل وراثة معقدة وفوضى في البيانات. فشاشات التلفزيون والحواسيب المحمولة تتبع نفس القسم لكنها تختلف كلياً في المواصفات (الشاشات تهتم بتقنية اللوحة والمنافذ والتردد؛ والحواسيب تهتم بالمعالج والرام). حصر المخططات في `product_type` يضمن أن كل منتج يُدرج وفق مخطط دقيق وغير مبهم.

### القاعدة 2.2: تسلسل التبعية الحاسم (Placement Validation)
تتحقق دالة الفحص `validateNodePlacement` في `lib/utils/tree.ts` من صحة علاقة الأصل والفرع:
- القسم الرئيسي (`department`) يجب أن يكون في المستوى الجذري حصراً (`parent_id = null`).
- التصنيف (`category`) يتبع قسماً رئيسياً فقط.
- التصنيف الفرعي (`subcategory`) يتبع تصنيفاً فقط.
- نوع المنتج (`product_type`) يتبع تصنيفاً أو تصنيفاً فرعياً.
- نوع المنتج (`product_type`) لا يمكن أن يحتوي أي تفرعات إطلاقاً.

```typescript
export const ALLOWED_CHILDREN: Record<Category['node_type'], Category['node_type'][]> = {
  department: ['category'],
  category: ['subcategory', 'product_type'],
  subcategory: ['product_type'],
  product_type: [],
};
```

### القاعدة 2.3: المسارات المحسوبة ديناميكياً
لمنع انحراف أو تباين البيانات:
- عمق العقدة ($0, 1, 2, 3$) **لا يُحفظ** كحقل يدوي قابل للتعديل، بل يُستنتج برمجياً من سلسلة الآباء.
- المسار النصي الكامل (مثل: `"الكهرباء والإنارة / الإضاءة / لمبات"`) يُحسب ديناميكياً من الأصل إلى الفرع، وبالتالي فإن تعديل اسم أي أب ينعكس فوراً وتلقائياً على جميع الفروع التابعة.

## 3. خوارزمية منع الحلقات الدائرية (Subtree Disqualification Algorithm)

عند نقل أي تصنيف وتغيير أصله التابع له (Reparenting)، يجب منع حدوث أي حلقة دائرية تسبب انهيار شجرة العرض (مثل جعل التصنيف الأب ابناً لأحد فروعه).

تطبق الأداة خوارزمية استبعاد التفرع بالكامل (`getForbiddenParentIds` في `lib/utils/tree.ts`):

```typescript
export function getForbiddenParentIds(categoryId: string, categories: Category[]): Set<string> {
  const forbidden = new Set<string>();
  
  // 1. لا يمكن للتصنيف أن يكون أصلاً لنفسه
  forbidden.add(categoryId);
  
  // 2. الأصل الحالي مستبعد لأنه الأصل الفعلي
  const target = categories.find(c => c.id === categoryId);
  if (target && target.parent_id) {
    forbidden.add(target.parent_id);
  }
  
  // 3. استبعاد جميع الفروع والأحفاد المندرجة تحت هذا التصنيف بالكامل
  const descendants = getDescendants(categoryId, categories);
  for (const desc of descendants) {
    forbidden.add(desc.id);
  }
  
  return forbidden;
}
```

### التأثير الفوري في واجهة المستخدم:
- يتم تعطيل أي تصنيف يقع ضمن قائمة `forbiddenParentIds` تلقائياً في القوائم المنسدلة لاختيار الأب الجديد.
- في حال إرسال طلب غير صالح، يقوم مشغل قاعدة البيانات `check_taxonomy_parent_placement` برفض العملية فورياً مع رمز الخطأ `23514`.

## 4. حوكمة الحذف والأرشفة الآمنة (Cascade Clean)

الحذف النهائي الفعلي غير مسموح للعقد التي تحتوي على عناصر نشطة:
1. **فحص الأبناء**: إذا كان التصنيف يحتوي على تصنيفات فرعية نشطة، يتم حظر الحذف:
   $$\text{عدد الأبناء النشطين} > 0 \implies \text{رفض: "لا يمكن حذف التصنيف لأنه يحتوي على فروع نشطة"}$$
2. **فحص الخصائص**: إذا كان نوع المنتج مرتبطاً بخصائص نشطة، يُمنع حذفه حتى تُفك الارتباطات أولاً.
3. **الأرشفة الآمنة**: تُعدل حالة العقد المؤرشفة إلى `status = 'archived'` مع تسجيل وقت الأرشفة `archived_at`، مما يحافظ على تكامل البيانات والتقارير التاريخية.
